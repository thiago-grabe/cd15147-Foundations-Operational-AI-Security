================================================================================
ROOT CAUSE ANALYSIS
================================================================================

Primary Cause:
A new report generation feature deployed in v2.4.8 contained a query that
performed a full table scan on the events table (approximately 500M rows) when
generating custom date range reports. This query was triggered by a customer
(Atlas Manufacturing) at 08:45 AM, consuming all available database connections.

Contributing Factors:
1. The problematic query was not caught in code review due to insufficient
   test data in staging environment
2. No query timeout was configured for the reporting module
3. Database connection pool monitoring alerts were set too high (95% threshold)
4. The feature was deployed on Friday afternoon without proper monitoring coverage

Technical Details:
- Affected query: SELECT * FROM events WHERE customer_id = ? AND created_at
  BETWEEN ? AND ? ORDER BY created_at
- Missing index on (customer_id, created_at) compound key
- Query execution time: 45+ minutes before killed
- Connection pool size: 100 connections (all consumed)
