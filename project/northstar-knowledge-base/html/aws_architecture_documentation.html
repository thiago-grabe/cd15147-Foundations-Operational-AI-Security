Architecture Overview

Northstar Technologies operates a multi-tier, highly available architecture on Amazon Web Services (AWS). Our infrastructure is designed for scalability, reliability, and security, following AWS Well-Architected Framework best practices.

AWS Services Breakdown

Amazon EC2 (Elastic Compute Cloud)

Purpose: Hosts our web application servers and API servers.

  • Auto Scaling Groups configured for automatic capacity management
  • Instances deployed across multiple Availability Zones (us-east-1a, us-east-1b)
  • AMI: Custom Amazon Linux 2 with pre-installed dependencies
  • Instance Profile: northstar-ec2-role (access to S3, CloudWatch, Secrets Manager)

Amazon EKS (Elastic Kubernetes Service)

Purpose: Runs containerized microservices for API layer.

  • Kubernetes version: 1.27
  • Node groups: 3 m5.large instances (managed node group)
  • Services: api-gateway, auth-service, data-service, reporting-service
  • Ingress: AWS ALB Ingress Controller

Amazon RDS (Relational Database Service)

Purpose: Managed PostgreSQL database for application data.

  • Engine: PostgreSQL 14.7
  • Multi-AZ deployment for high availability
  • Automated backups: 7-day retention
  • Read replica for reporting workloads
  • Parameter group: northstar-pg14-params (optimized for our workload)

Amazon ElastiCache (Redis)

Purpose: In-memory caching for session management and frequently accessed data.

  • Engine: Redis 7.0
  • Cluster mode: Disabled (single shard)
  • Use cases: Session storage, API response caching, rate limiting counters

Amazon S3 (Simple Storage Service)

Purpose: Object storage for assets, backups, and logs.

Amazon CloudFront

Purpose: Content delivery network for static assets and web application.

  • Distribution ID: E1234567890ABC
  • Origins: S3 (assets), ALB (dynamic content)
  • Price Class: PriceClass_100 (North America & Europe)
  • SSL Certificate: ACM certificate for *.northstartech.com

Amazon SQS & SNS

Purpose: Message queuing and notification services.

  • SQS Queues:
    • order-processing-queue: Standard queue for order events
    • notification-queue: Standard queue for outbound notifications
    • export-queue: Standard queue for data export jobs
  • SNS Topics:
    • system-alerts-topic: Critical alerts → PagerDuty, Slack
    • deployment-notifications: Deploy events → Slack #deployments

Security Configuration

Security Note: All access to production resources must go through approved channels. Direct SSH access is prohibited. Use AWS Systems Manager Session Manager for instance access.

Network Security

  • VPC: Dedicated VPC with public/private subnets across 2 AZs
  • Security Groups: Least-privilege access, no 0.0.0.0/0 inbound rules
  • NACLs: Default deny with explicit allow rules
  • AWS WAF: Rate limiting, SQL injection protection, geo-blocking

IAM Configuration

  • Separate IAM roles for each service component
  • Permission boundaries enforced on all roles
  • MFA required for console access
  • No long-lived access keys in production

Data Encryption

  • At Rest: AWS KMS with customer-managed keys
  • In Transit: TLS 1.3 for all external connections
  • Database: RDS encryption enabled
  • S3: Server-side encryption (SSE-KMS)
