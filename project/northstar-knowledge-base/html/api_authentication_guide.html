Overview

The Northstar API supports multiple authentication methods to accommodate different use cases and security requirements. All API requests must be authenticated using one of the following methods:

  • API Keys - Best for server-to-server integrations
  • OAuth 2.0 - Best for user-facing applications
  • JWT Tokens - Best for microservices and short-lived sessions
Base URL: All API requests should be made to https://api.northstartech.com/v2

API Key Authentication

API keys provide a simple way to authenticate server-to-server requests. Each API key is associated with a specific account and has configurable permissions.

Generating an API Key

  1. Log in to the Northstar Dashboard
  2. Navigate to Settings → API Keys
  3. Click Generate New Key
  4. Select the appropriate permissions for your use case
  5. Copy and securely store your API key (it will only be shown once)

Using API Keys

Include your API key in the Authorization header:

curl -X GET "https://api.northstartech.com/v2/users" \
  -H "Authorization: Bearer ns_live_abc123xyz789" \
  -H "Content-Type: application/json"

API Key Types

Prefix Type Description
ns_live_ Production Full access to production data and operations
ns_test_ Test Access to sandbox environment only
ns_restricted_ Restricted Limited permissions, read-only access
Security Warning: Never expose API keys in client-side code, public repositories, or logs. Rotate keys immediately if compromised.

OAuth 2.0 Authentication

OAuth 2.0 is recommended for applications that access Northstar on behalf of users. We support the Authorization Code flow with PKCE.

OAuth Endpoints

Endpoint URL
Authorization https://auth.northstartech.com/oauth/authorize
Token https://auth.northstartech.com/oauth/token
Revoke https://auth.northstartech.com/oauth/revoke

Authorization Code Flow

Step 1: Redirect user to authorization endpoint

https://auth.northstartech.com/oauth/authorize?
  response_type=code&
  client_id=YOUR_CLIENT_ID&
  redirect_uri=https://yourapp.com/callback&
  scope=read:users write:data&
  state=random_state_string&
  code_challenge=BASE64_CHALLENGE&
  code_challenge_method=S256

Step 2: Exchange authorization code for tokens

curl -X POST "https://auth.northstartech.com/oauth/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=authorization_code" \
  -d "code=AUTHORIZATION_CODE" \
  -d "redirect_uri=https://yourapp.com/callback" \
  -d "client_id=YOUR_CLIENT_ID" \
  -d "code_verifier=ORIGINAL_CODE_VERIFIER"

Available Scopes

Scope Description
read:users Read user information
write:users Create and update users
read:data Read data and reports
write:data Create and modify data
admin Full administrative access

JWT Token Authentication

JSON Web Tokens (JWT) can be used for short-lived authentication, particularly useful for microservices architectures.

Token Structure

{
  "header": {
    "alg": "RS256",
    "typ": "JWT"
  },
  "payload": {
    "sub": "user_123",
    "iss": "https://auth.northstartech.com",
    "aud": "https://api.northstartech.com",
    "exp": 1687654321,
    "iat": 1687650721,
    "scope": "read:users write:data"
  }
}

Token Expiration

  • Access tokens expire after 1 hour
  • Refresh tokens expire after 30 days
  • Use the refresh token to obtain new access tokens without re-authentication

Security Best Practices

  1. Use HTTPS: All API requests must use HTTPS. HTTP requests will be rejected.
  2. Rotate Keys Regularly: Rotate API keys every 90 days or immediately if compromised.
  3. Principle of Least Privilege: Request only the scopes and permissions you need.
  4. Secure Storage: Store credentials in environment variables or secure vaults, never in code.
  5. Monitor Usage: Regularly review API access logs in the dashboard.
  6. IP Allowlisting: Enterprise accounts can restrict API access to specific IP ranges.

Troubleshooting

Common Errors

Error Code Message Solution
401 Invalid or expired token Check token validity and refresh if expired
403 Insufficient permissions Verify your API key or token has required scopes
429 Rate limit exceeded Implement exponential backoff and retry
